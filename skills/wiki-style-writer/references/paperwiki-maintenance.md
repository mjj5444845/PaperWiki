# PaperWiki 首页、批次与发布约定

本文件只适用于 PaperWiki 仓库维护。用户已要求每次更新完成后提交并 push 到仓库；这一要求包括内容、首页设计、自动化与 skill 更新，不应仅停留在本地修改。用户明确要求暂不提交或推送时，以当次指示为准。

## 首页与导航

- 首页第一句话固定为“这里收录人机交互及相关领域的论文介绍”。不要自行扩展为概念页说明或列举更多领域。
- 首页只在顶部保留一个“本批新增论文”区域，删除底部“最近新增论文／最近新增页面”等重复区域。
- 本批论文与下方每个领域的论文使用同一列表渲染方式：标题链接到真实论文页面，下面显示灰色字的缩略概览。复用 `build.py` 的 `listing()` 和已有 `.page-list` 样式。
- 首页内部链接也必须解析为可点击的站内地址，不能直接输出 `[[页面名]]` 文本。链接、页面预览和资源地址均遵守 `BASE_URL`，兼容根路径与 GitHub Pages 项目路径。

## 批次更新与领域归档

- `wiki/index.md` frontmatter 的 `latest_batch` 为当前批次标识，`latest_papers` 为该批论文的稳定 ID 列表；不要在正文另外维护一份手写链接清单。
- 每次发布新论文时更新顶部批次。同一次收件箱运行中成功发布的多篇论文合并为一批；手动新增时也为同批论文使用同一标识。新批次替换旧列表，同批追加并去重。
- 没有成功发布新论文时保留现有批次；重复扫描、失败、单纯修订旧文或修改样式不应清空或轮换批次。顶部无需显示历次批次的累积名单。
- 所有已发布论文始终保留在对应领域目录；旧批次移出顶部后仍可在下方领域找到。本批论文也可在领域目录中出现。
- 已设立“人类与机器人交互”领域。2026-11-02 本批六篇中，五篇机器人主题论文归入该领域；《Participatory design: a systematic review and insights for future practice》是通用参与式设计综述，归入现有“设计研究与方法”。以后按论文自身的核心主题分类，不能因同批导入、与机器人论文互引或方法可用于机器人研究而自动归入机器人领域。
- 分类要同步更新注册表的 `field`、论文 frontmatter 的 `field` 和信息框的“领域”，使首页、搜索和论文页一致。
- 自动流程通过 `automation/content.py` 的 `update_home_batch()` 更新批次；首页修改须在生成发布校验哈希前完成，并纳入 `automation/depth.py` 的 `artifact_hashes`。保留论文与概念正文的既有独立审核要求。

## 完成更新与推送

1. 查看工作区差异，完成用户已授权的本轮修改，包括相关文档与规则；只提交本次相关且可公开的文件。原始 PDF、私有笔记、状态日志与凭据继续遵守仓库忽略规则。
2. 按改动运行必要检查。涉及首页、构建或批次逻辑时运行 `python build.py`、`python -m unittest discover -s tests` 和 `python check.py`；使用仓库可用的 Python 环境。检查真实链接目标、列表概览、批次轮换和领域归档。纯文档修改可使用相应的格式、引用与 skill 校验。
3. 检查 `git diff --check` 和待提交清单，以说明最终行为的提交信息 commit，然后 push 到当前任务所用分支。当前仓库常规维护分支为 `main`；不要擅自切换分支或强制推送。
4. 确认远端分支包含该提交后才报告“已推送”。常规 push 已获用户持续授权，无需每轮再次确认。遇到权限、网络或远端冲突，保留工作并说明实际阻碍；不要用强制推送覆盖远端。
5. 网站更新推送后检查 GitHub Pages 工作流与线上结果；区分“本地完成”“已推送”“已部署验证”，不要将构建成功等同于上线成功。
