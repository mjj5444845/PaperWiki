**人工智能素养**（AI literacy）是使人能够批判性评价人工智能、有效与之沟通协作，并在网络、家庭和工作中使用AI的能力集合。Long与Magerko的定义强调理解、判断及使用，而不把编写程序设为所有人的入门门槛。它既涉及技术和数据，也涉及系统可能影响谁、何时应该质疑结果等社会问题。[^s1]

## 素养不等于会用一个产品

会点击生成按钮或输入提示词，可能只是掌握某一界面。人工智能素养进一步要求辨认系统在什么意义上具有智能、怎样从资料学习、其输出为何可能不可靠，以及人能怎样参与和控制过程。2020年框架因此没有将“多用某个软件”当成完整目标，而把能力与学习体验设计联系起来。[^s1][^r1]

Long与Magerko区分几种邻近素养。数字素养帮助人使用计算设备，因而被视为前提；编程有助于理解AI，也对开发者必要，但日常使用者不必都具备。科学素养可以帮助理解研究方法，却不被设为严格前置；[[数据素养]]则与[[机器学习|机器学习]]中的资料理解重叠。这种区分让学习目标能够面向非技术群体，而不以工程训练筛去大部分公众。[^s1]

## 能力框架怎样组织理解

2020年研究从“AI是什么、能做什么、怎样运作、应怎样使用、以及人怎样看待它”等问题组织能力。其目的不是让学习者背一张产品名单，而是形成能迁移到不同系统的提问方式。例如，识别推荐和识别照片都使用数据，并不意味着两者的训练目标、错误后果和使用边界相同。[^r1]

论文的17项能力可依原文编号展开如下。各项涵盖理解、判断和行动，不能以熟悉某一产品代替。[^r1]

| 编号与能力 | 需要掌握的内容 |
|---|---|
| 1 识别AI | 区分使用与未使用AI的技术对象 |
| 2 理解智能 | 比较人、动物和机器智能的不同含义 |
| 3 跨学科性 | 认识认知系统、机器人和机器学习等不同路线 |
| 4 通用与狭义AI | 区分跨领域能力与特定任务能力 |
| 5 优势与弱点 | 判断哪些问题适用AI、哪些需要人的技能 |
| 6 想象未来AI | 设想应用及其可能后果 |
| 7 知识表示 | 理解信息如何表示，并举出表示方式 |
| 8 决策 | 说明计算机推理和作决定的例子 |
| 9 机器学习步骤 | 理解学习流程及各步骤中的实践与挑战 |
| 10 人的角色 | 认识编程、选模型及调节系统中的人为选择 |
| 11 数据素养 | 掌握理解和使用数据的基础 |
| 12 从数据学习 | 知道计算机从数据中寻找模式 |
| 13 批判解释数据 | 认识数据需要解释，说明初始训练例子怎样影响算法结果，并质疑资料与预测中的假设和局限 |
| 14 行动与反应 | 认识部分AI能够物理作用于世界，区分高层推理引导的行动（如按规划路径行走）与反应式行动（如避开感知到的障碍） |
| 15 传感器 | 解释传感器的作用并辨认不同设备中的传感器，认识不同传感器支持对世界的不同表示和推理 |
| 16 伦理 | 辨认并说明关键伦理议题的不同立场，包括隐私、就业、错误信息、奇点、伦理决策、多样性、偏见、透明度与问责九类议题 |
| 17 可编程性 | 知道智能体的行为可以被编程改变 |

这些能力属于文献综合提出的框架，原文没有将它们验证为一套统一考试。可编程性要求理解行为可以被人设定，并不与日常使用者无需先掌握编程语言的立场矛盾。[^r1]

## 学习体验为何需要设计

对于看不见内部过程的系统，只告诉学习者“机器学会了”，容易形成近似魔法的解释。该文建议让学习者观察过程、进行探索并反思，帮助抽象机制与可体验的反馈连接。这里的可观察不要求人人阅读源代码，也不应以容易理解的比喻替代系统真实限制。[^r2]

资料本身也是学习对象。学习者若只看最终预测，不易知道例子怎样影响规则、资料缺失如何限制判断。让人检视和参与资料，可以把“模型来自数据”变成可讨论的具体关系；但一项教学演示不能自动代表大型生产模型的所有行为。设计考量是开发学习体验的方向，而不是对任一演示有效性的证明。[^r2]

该框架也重视社会情境：学习者已有关于AI的认知和误解，可能来自影视、日常设备或媒体叙述。教育不应只从术语定义开始，还需知道对方已经怎样理解机器。技术能力、数据判断和伦理问题因此可以在同一任务中被讨论，不必把价值问题留成课程最后的附录。[^r1][^r2]

原文的15项设计考量把能力目标转成学习体验安排。它们针对理解过程、学习者差异和参与条件，所依据研究及适用条件各不相同。[^r2]

| 考量 | 具体设计含义 |
|---|---|
| 1 解释性 | 用可视化、模拟、决策解释或交互演示帮助理解机制 |
| 2 具身交互 | 让学习者以身体演出算法、操纵材料或通过动作训练系统，把抽象步骤转成可体验活动 |
| 3 数据情境化 | 初学可从较少维度开始，再接触与自己有关及未经整齐清理的真实数据，理解资料从何而来 |
| 4 促进透明 | 不只显示内部步骤，还说明创作者意图、资金和数据来源，并改善文档 |
| 5 渐进揭示 | 一次解释少量组成，允许按需检查，随理解增加逐渐移除支架，避免过载 |
| 6 编程机会 | 提供编程或教导智能体的途径，以视觉、声音或填空代码等降低先备要求 |
| 7 发展里程碑 | 依年龄、心智发展和技术经验调整解释，特别注意儿童对智能体的理解 |
| 8 批判思考 | 鼓励质疑机器的智能、可信程度和能力边界，避免把友好表现等同可靠 |
| 9 身份、价值与背景 | 考虑文化和个人经验如何影响兴趣、理解与参与动机 |
| 10 支持家长 | 为家庭中的成人提供材料和支架，帮助其支持儿童探索，而非只向儿童交付设备 |
| 11 社会互动 | 创造同伴协作、讨论与共同学习机会，利用社会活动促进理解 |
| 12 学习者兴趣 | 从日常生活、音乐、游戏或关心的议题连接AI概念 |
| 13 承认既有成见 | 识别影视、新闻和政治叙述带来的预想，再据此回应和扩展 |
| 14 新视角 | 引入媒体较少呈现的AI领域，并平衡讨论利益与风险，避免只剩机器人或末日叙事 |
| 15 低门槛 | 减少对数学和计算机知识的预先要求，连接旧知识并回应能力焦虑 |

透明与解释性由此具有不同范围：一个界面即使清楚解释预测，也可能没有说明谁提供训练数据、谁资助或为何开发。发展里程碑与家长支持则承认学习发生在人与人关系中；同一种机器拟人表现，对成人和儿童不一定具有相同含义。框架把这些条件与技术内容并列，而非只追求更详细的算法动画。[^r2]

### 以分类器探索为例

一个据框架构造的说明性学习任务，可以让学习者先给少量图片分类，再训练一个演示分类器。第一步说明标签怎样把现实转换成表示；第二步比较训练和测试输入，观察预测并不等于读取标准答案；第三步增减某一类例子，记录错误怎样变化，把“从数据学习”与人的数据选择联系起来。这个说明性任务把框架中的多项能力连接到同一学习流程。[^r1][^r2]

学习者还可以检查没有覆盖的图片类型、讨论若系统用于有实际后果的场景会影响谁，并说明可以怎样修改标签或训练资料。检查理解时，可要求其解释一次错误来自哪些已知条件，以及还缺什么证据，而不只是复述系统名称。若让机器人执行分类后的动作，则可继续观察传感器输入与行动反应；界面应渐进显示这些环节，家长或同伴可以协助提出和比较假设。[^r1][^r2]

## 发展：面向不同学习者的能力目标

UNESCO于2024年发布学生AI能力框架，组织为以人为本的心态、AI伦理、技术与应用、系统设计四维，并设置理解、应用、创造三个进阶层次，共12项能力。它面向正式课程，强调负责任的使用者与共同创造者。该框架与2020年的概念定义相关，但不是简单采用同一17项清单，也不能把两个版本的数字混为同一测验。[^e]

这种差异说明“素养”可以因受众和课程目标而操作化。非技术公众、学校学生与AI开发者承担的任务并不相同；是否需要编程、训练系统或更深入数学，应依角色确定。Long与Magerko为非技术学习者降低编程门槛，不表示专业开发无需理解实现，也不表示所有人都需达到同一层次。[^s1][^e]

## 判断理解与信任的边界

素养不能由使用频率直接推定。一个经常接触推荐的用户可能仍不清楚资料用途，一个会编程的人也可能不了解某应用对不同群体的后果。框架把批判评价写入定义，正是为了避免把熟练使用与不加质疑的接受混为一谈。[^s1]

2020年论文的证据来自150份跨领域文献和灰色资料的探索性综述，方法接近范围研究，作者明确不称其为穷尽的系统综述。框架能够组织研究问题与学习设计，但并未提供对所有年龄、文化和课程的完整成效验证。把概念框架当成已经标准化的测量工具，会超过原文的证据。[^s2]
