**启发式评估**（英语：heuristic evaluation）是评估者依据一般[[可用性]]原则检查界面、指出潜在使用问题的评价方法。评估者需要说明问题在哪里以及为什么妨碍使用，而不是仅给整个界面打一个好坏分。多人先独立检查再汇总，可以利用不同观察者发现问题的互补性。1990年的研究采用九项原则，后来常用的十项版本另有修订；检查报告的是潜在问题，该研究没有用传统用户测试验证全部问题清单。[^s3][^r1][^e]

## 检查怎样进行

1990年的研究要求评估者书面报告问题，再将报告与已知问题列表匹配。作者在阅读报告后还补充了自己原先遗漏的问题，说明作为评分参照的列表本身也会修订。检查由此产出可讨论的具体发现，而不是证明界面已经不存在问题。[^r1]

一份可操作的发现通常包含界面元素、发生条件、违反的原则及用户可能遇到的后果。例如原研究中，Transport语音系统从子菜单转回主菜单时没有停顿或层级提示，评估者会把它识别为反馈和导航问题。报告需要解释用户为什么可能误以为仍在原来的菜单中，而不能只写“违反一致性”。[^r1]

## 1990年的九项原则

《[[Heuristic Evaluation of User Interfaces|Heuristic Evaluation of User Interfaces]]》采用九项原则。它们是概括性的判断依据，不能替代对具体用户、任务及界面状态的理解。下面是依据原文原则名称整理的释义。[^s3]

| 原则 | 检查重点 |
|---|---|
| 简单自然的对话 | 信息和步骤是否按用户任务安排，是否存在无关内容 |
| 使用用户语言 | 表达是否符合使用者熟悉的词汇，而非内部术语 |
| 减少记忆负担 | 是否让用户反复记住前面出现却已不可见的信息 |
| 一致性 | 同一含义和操作是否采用一致约定 |
| 反馈 | 系统是否使用户知道操作与当前状态 |
| 明确标出的出口 | 进入不需要的状态后能否找到退出方式 |
| 快捷方式 | 熟练用户是否有更高效的操作途径 |
| 良好的错误信息 | 错误说明是否清楚，并帮助理解或恢复 |
| 预防错误 | 是否能在错误发生前减少诱因 |

论文提供了能看到原则怎样落地的例子：Mantel显示查询结果时覆盖刚输入的电话号码；Teledata使用难以理解的“UNKNOWN IP”；语音系统采用不同的按键约定。它们分别涉及记忆负担、用户语言及一致性，而不只是视觉外观。[^r1]

## 独立检查与合并

单人检查很容易遗漏问题。1990年四项研究由非可用性专家评估：Teledata为37名受过启发式课程的计算机专业学生，Mantel为77份主要来自业界计算机专业人员的竞赛投稿、未受该课程培训，Savings和Transport由同一批34名受过课程的计算机专业学生检查。四项的平均个人发现比例依次为51%、38%、26%与20%，均以各界面的已知问题集合为分母；这些数值描述上述不同人员与培训条件，不是可用性专家的一般发现率。[^sample]作者还发现，发现问题多的人也会漏掉其他人发现的容易问题，因此不能只选择一个“最好”的评估者来替代多人检查。[^r2]

多人发现的曲线来自对独立报告作模拟组合，并假设成员发现能够理想汇总，不是将真实团队随机分组后的对照结果。独立检查后再汇总是作者据此提出的安排建议。作者建议通常组织3—5人，原因是合并发现能明显增加覆盖，而继续增加人数的边际收益逐渐降低。这个建议是资源与发现收益的折中，不表示三个人必然发现某个固定百分比的问题；界面、人员和参照集合都会改变结果。[^r2]

语音界面还暴露了呈现方式的影响：消息说完就消失，评估者难以像查看纸面那样反复比较细节。因而，个人发现比例的差异不能简单归因于人的能力，检查材料能否保持可见也会影响评估。[^r2]

## 后来的原则与领域适配

Nielsen后来公布的十项启发式原则是另一版本，包含系统状态可见、符合现实世界、用户控制、一致性、预防错误、识别优于回忆、灵活高效、简洁设计、错误恢复及帮助文档。它与1990年九项原则存在继承和调整，1990年论文原表列出九项，而非后来版本的十项。[^e]

领域性指南可以保留启发式检查的组织方式，同时更换检查依据。《[[Guidelines for Human-AI Interaction|Guidelines for Human-AI Interaction]]》用指南评估人工智能产品中的交互实例，重点包括能力边界、错误纠正及随时间变化的行为。此时评估的不只是传统菜单是否清楚，还包括不确定系统应如何设置预期。[^s2]

## 局限与证据

启发式评估指出的是潜在问题，不能保证每项判断在真实任务中都会造成困难。1990年论文没有以传统[[可用性测试]]验证全部列表，且研究范围主要是较小、整体设计已成形的界面。作者也没有正式分析误报比例，其误报水平因而未被该研究量化。[^r1][^r2]

原则本身也不能决定所有权衡。让初学者看到更多解释可能增加熟练用户的操作负担；是否修改，需要结合受影响人群和任务后果。作者建议用[[出声思考法]]等实际使用观察补充检查，并在争议时寻求进一步证据。[^r2]

## 在本站论文中的应用

《Heuristic Evaluation of User Interfaces》采用Molich与Nielsen另一篇1990年论文整理的九项原则，并用四种界面检验个人与多人检查的发现情况。它的关键结果是单人覆盖有限且发现不完全重合，由此支持独立评估后的汇总，而非证明一份原则清单能够保证设计合格。[^s3][^r2]

《Guidelines for Human-AI Interaction》将启发式检查用于人工智能交互指南的开发和检验。内部评估与后续研究收集指南适用的正反实例，并据难以理解、难以区分或不适用的情况修订指南。这是原则与实例之间的迭代，不是把传统九项或十项原封不动应用于所有人工智能界面。[^s2]
