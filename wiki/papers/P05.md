《用于交互桌面的用户自定义手势》（User-Defined Gestures for Surface Computing）是 Jacob O. Wobbrock、Meredith Ringel Morris 与 Andrew D. Wilson 于2009年发表的输入设计研究。作者不先教用户一套手势，而是先播放操作结果，再请没有触屏经验的参与者演示自己认为能产生该结果的动作。20人针对27个命令各提出单手和双手版本，共产生1080个手势，其中1074个进入分析。研究依据动作分类、参与者共识及口述思考，形成包含48个动作的手势集，并发现桌面软件经验、手指数目的宽容使用以及单手偏好会影响设计。它提供的是用户引出的候选输入语言，而不是已经实现识别器并验证完成速度的产品评价。[^p1][^p4][^p6]

## 背景：设计者会用，不等于用户会猜

交互桌面允许用户直接用手操作图形，输入空间比鼠标按键大得多：手指、手掌、双手组合与运动路径都能成为命令。此前一些系统由设计者定义手势，常用是否容易识别来决定动作。作者认为，这种方式适合探索原型，却未必反映没有训练的用户会自然尝试什么。尤其公共场所中的交互桌面，可能需要首次使用者当场猜出操作，而不能总依靠长时间学习。[^p1][^p3]

本研究采用[[手势引出]]（gesture elicitation）或可猜测性研究：把预期效果称为 referent，把用户提出的动作称为 sign。相关方法在命令词和笔画输入研究中已有先例，因此论文的贡献不是发明“让用户参与”本身，而是把它系统用于桌面手势，结合定量记录、分类和[[心智模型|心智模型]]解释。[^p2]

作者刻意取消识别反馈。如果识别器不断拒绝某些动作，用户就会改成机器能认出的动作，研究最后测到的可能是适应识别器后的习惯，而非初始预期。因此系统只记录触碰，不判断提案对错。这让设计者观察到机器尚不支持的动作，也同时使研究无法回答实际识别率和学习后的使用表现。[^p3][^p9]

## 研究材料与过程

20名付费参与者来自一般公众，其中9人为女性；全部右利手，平均43.2岁，标准差15.6。没有人用过交互桌面、Apple iPhone 或类似触屏设备，也不是计算机科学家或界面设计师。职业包括餐厅接待、音乐家、作者、钢铁工人等。这样的招募用于减少专业设计及触屏习惯的影响，但并没有排除他们对传统桌面计算机的经验。[^p3]

设备为24×18英寸、分辨率1024×768的 Microsoft Surface 原型，C#程序播放预录动画和语音说明。界面只有二维几何图形，没有 Windows 或 Macintosh 的特定控件，也不假定某种专业应用。桌底视觉系统把接触记录成带毫秒时间戳的椭圆，四个角度的录像和两位作者的观察笔记补充了接触日志无法解释的意图。[^p3][^p4]

每个命令以随机顺序呈现。参与者先看效果和说明，再分别作单手、双手动作，同时说出思考过程；每完成一个手势，就在两项七点量表上评价“与目的匹配得好不好”和“容易不容易做”。两种动作都完成后，再表明手数偏好。$20\times27\times2=1080$次提案中，六次因参与者困惑被剔除。动作看起来相似时，口述资料帮助研究者分辨它是物理操作、隐喻还是任意符号。[^p4]

27个效果覆盖移动少量／大量、单选／组选、旋转、缩小／放大、删除、平移、关闭、缩放视野、打开、复制、上一个／下一个、插入、最大化、粘贴、最小化、剪切、接受、拒绝、菜单、帮助、任务切换和撤销。三位作者事先按1至5评价概念复杂度，例如移动为1，撤销为5。这是研究者的评价，不能当作参与者实际难度评分。[^p4]

## 四维分类怎样描述手势

分类首先区分动作如何发生，再区分它为何与命令关联。相同的点击轨迹可能表示碰物体，也可能是在按想象中的按钮，因此只看触点数据不足以完成全部分类。作者逐个手工分类，并明确把双手动作的形式分别编码。[^p4]

| 维度 | 完整类别及含义 |
|---|---|
| 形式（form） | 静态姿态、原地变化的动态姿态、保持姿态并移动、改变姿态并移动；另区分近似鼠标的一点触碰与一点路径 |
| 性质（nature） | 符号式：画出有意义符号；物理式：像直接作用于实物；隐喻式：借另一行动或对象理解命令；抽象式：动作与含义任意对应 |
| 绑定（binding） | 以对象为中心、依赖整体空间、不依赖整体空间（位置可忽略空间特征，并可避开临时出现的对象）、混合依赖（空间独立成分与另一类依赖并存）；区分动作需落在对象、屏幕某位置还是任意处 |
| 流程（flow） | 离散式：动作完成后触发一次响应；连续式：动作进行时持续控制结果 |

例如在对象上捏合缩小，是对象中心的物理动作；在右上角点击想象的关闭按钮，则依赖空间位置并借用控件隐喻。画问号调用帮助是离散的符号动作，拖动改变大小则往往需要连续反馈。所谓一点触碰也可用随意靠在一起的两三根手指完成，只要用户心中仍把它当一个接触位置。[^p4][^p5]

按动作性质分组，其所对应命令的平均概念复杂度分别为物理2.11、抽象2.99、隐喻3.26、符号3.52；回归分析报告差异显著。这表示较简单的命令较常引出类似直接作用于实物的动作，不等于每个复杂命令都只能用符号，更不是证明某类动作在实际系统中速度更快。[^p5]

## 从提案得到共识，再解决冲突

对一个命令，研究者把相同动作分组。若该命令共有 $n$ 个提案，第 $j$ 组有 $n_j$ 个，则其一致性为：

$$A_r=\sum_j\left(\frac{n_j}{n}\right)^2,\qquad A=\frac{1}{|R|}\sum_{r\in R}A_r$$

$A_r$ 描述效果 $r$ 下提案的集中程度，$R$ 是全部效果集合，$A$ 是跨效果平均。若每个人都给出不同动作，它仍为 $1/n$；若全部一致，才为1。它不是“猜对比例”，因为研究中没有事先规定唯一正确答案。[^p5]

论文的双手少量移动例子有四组，人数为12、3、3、2，故平方比例相加得到约0.42。单手选择一个对象则为11、3、3、3，得到0.37。两者虽然都有四种提案，前者更集中于主流动作，因此一致性较高。整体单手一致性为0.32，双手为0.28；命令复杂度与一致性呈负相关，$r=-0.52$，$p<0.01$。[^p5]

手势集不能直接把每个命令最受欢迎的动作拼起来。同一个动作若用于两个含义，就会冲突；作者将它分配给支持人数较多的那个效果，再考虑其他候选。最终集合没有此类命令冲突，覆盖全部提案的57.0%，而不是覆盖57%的命令或达到57%的识别准确率。保留同一命令的多种别名动作，也让不同用户有更多机会猜到可接受输入。[^p5][^p6]

## 最终手势集包含什么

论文把两个移动效果合并，得到22个有专门动作的命令类别、48个动作。31个为单手、17个为双手。插入与最大化没有独立动作，因为可以由拖动和放大等原始动作完成；关闭与任务切换的提案常依赖想象中的按钮，不宜硬编一个共识不足的动作。省略项本身也是设计结果。22类中，10类各有1个动作、4类各有2个、3类各有3个、4类各有4个、1类有5个；最终集合的分类比例与全部提案平均相差6.7个百分点。[^p5][^p6]

下表以文字整理原文图4的动作族；可逆对分别沿反方向执行。[^p7]

| 命令类别 | 提出的动作及复用关系 |
|---|---|
| 移动 | 拖动物体；或一手指向源位置、另一手指向目的位置使对象跳转 |
| 单选、组选 | 点击或圈选单个对象；组选可按住并逐个点击，或将单选动作扩展至多个对象 |
| 旋转 | 触碰对象角部并沿旋转方向拖动 |
| 放大／缩小 | 两手拉开／合拢、两指拉开／合拢、捏合，以及手指张开／收拢等四种可逆方式 |
| 放大／缩小视野 | 复用尺寸变化动作，但作用于背景而非对象 |
| 打开 | 双击；或对可打开容器使用四种放大动作 |
| 平移 | 拖动手掌或手来移动背景内容 |
| 删除、最小化 | 删除可拖或跳至屏外；最小化则移至使用者所在方向的桌面底部 |
| 复制 | 点击来源与目的位置；完成后来源不再保持选中 |
| 剪切、粘贴 | 剪切在已有当前选择的前提下用划切动作；粘贴可点击或从屏外拖入、以跳转方式从屏外带入 |
| 上一个／下一个 | 在对象上沿相反方向划线 |
| 接受、拒绝 | 画勾接受、画叉拒绝；可见对象的拒绝也可复用删除动作 |
| 菜单、帮助、撤销 | 拉出菜单、画问号、用划掉式动作撤销 |

复用依赖动作落点，不能只看轨迹。五指张开在对象上表示放大，在背景上表示放大视野，在可打开容器上可以表示打开。这个安排让相近概念共享身体动作，同时用对象与背景区分意义。论文也发现参与者常把放大、最大化或缩放视野视为类似事情，设计者的概念区分不一定是用户的区分。[^p6][^p8]

## 数字背后的行为解释

| 观察 | 数值与口径 | 对设计的含义 |
|---|---|---|
| 手数偏好 | 27个效果中25个总体偏好单手，插入与最大化两项平分 | 不应因为桌面支持双手就强迫所有命令使用双手 |
| 规划时间 | 简单效果约8秒，复杂效果约15秒；复杂度与规划时间 $r=0.71$ | 复杂命令的主要困难可能在想出动作，而非动作执行本身 |
| 匹配感 | 简单效果手势平均约5.6，复杂效果约4.9，满分7 | 较难构思的动作也较少被认为与目的相配 |
| 执行与容易程度 | 被评为容易的动作约3.4秒，困难的约2.0秒 | 容易并不等于快，较平顺、较不匆忙是作者提出的可能解释 |
| 专家覆盖用户集合 | 每位作者单独提出43.5%，三人合起来60.9% | 专家经验不能完全替代引出公众提案；这不是专家系统与用户系统的性能竞赛 |

这里的执行时间是在提出动作的研究情境下测得，并非熟练操作效率。参与者偏好单手也不意味着双手动作应全部排除：一些双手动作有不错的一致性，并能与单手版本互补。论文将主观匹配、容易程度与时间分开处理，避免把它们混成一个“最佳手势”分数。[^p6][^p8]

同一动作提案的群体越大，参与者给出的主观匹配评分越高，$\chi^2(1,N=1074)=34.10$，$p<0.0001$。这为依据群体共识选择动作提供了验证，但验证的是主观匹配，不是识别器表现。命令概念复杂度与匹配评分呈负相关（$r=-0.59$），与容易程度则没有显著相关。规划时间越长，匹配评分越低，却不显著影响容易程度；执行时间影响容易程度，却不显著影响匹配评分。作者据此区分了“想到适合动作”与“身体容易做”这两个问题。[^p6]

接触事件包括按下、移动与抬起，其数量也显著影响容易程度评分，$\chi^2(1,N=1074)=21.82$，$p<0.0001$。被评为容易的动作，其事件数约为困难动作的两倍。原文把事件数视为活动量的粗略指标，较长动作自然也会产生更多事件；这不是能耗测量。作者推测，较长动作可能更平顺或不那么仓促，但未把这一解释作为已独立检验的机制。[^p6]

13人会改变接触手指数，其中只有2人认为数量本身有意义；有人觉得大物体需要更多手指，或用更多接触保证按到。整体约72%的动作是类似鼠标的一点触碰或路径。虽然刺激没有操作系统控件，人们仍模仿鼠标点击，或在想象中的任务栏、右上角操作，这显示旧经验可以跨越刻意简化的界面。[^p8]

参与者还把屏幕外当成剪贴板或丢弃区，并作出桌面上方的托起、招手等动作。物理式动作占43.9%，支持考虑物理模拟；但符号、抽象与隐喻动作同时存在，仅用物理引擎也无法涵盖全部意图。识别硬件若只从下方看接触点，可能漏掉用户预期中的动作部分，这正是用户引出对技术设计的反向要求。[^p8][^p9]

作者还建议给共识较低的命令提供屏幕控件，而不是要求用户猜出唯一手势。对象角部有特殊意义，需要适当的命中检测，但操作不应要求过分精确：双手放大的14人中只有2人沿对角线调整，反向捏合的5人中只有1人沿对角线，其余使用侧向或其他方向。作者还建议把四指作为少量手指的一点接触与整手接触之间的边界，而不把每一个手指数绑定成不同命令。[^p9]

每位作者自己提出的动作中，平均19.1%无人提出，说明专家方案与公众提案存在双向差异，不能把研究简化为用户总比专家更会设计。[^p8]

## 局限与后续方法研究

本研究没有识别反馈、真实应用情境或后续修改机会。参与者不知道之后所有命令，不能在看见全集后重新统筹动作；全为有文字能力的美国成人、右利手及非技术人员，也限制了对儿童或其他文化群体的推广。作者提出下一步应让新参与者从无标签录像猜含义，并实现识别器测量实际表现；本文不能代替这些验证。[^p9]

Morris 等人在2014年讨论“旧经验偏差”（legacy bias）：人们可能把旧设备的习惯移植到新交互，提出增加提案数量、预先启发和结伴引出等改进。这具体延续了本研究中模仿鼠标的发现。Vatavu 与 Wobbrock 在2015年进一步形式化一致性分析，增加度量与显著性检验；因此2009年的平方比例分数应按其原始定义解释，不能不加区分地称为后来所有共识指标。[^e1][^e2]
